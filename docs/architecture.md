# 项目架构与目录说明

## 概览

CloverViewer 是一个基于 Tauri 2 的 Windows 桌面图像查看器和截图工具。它由 WebView 内运行的 TypeScript 前端、提供原生能力的 Rust 后端，以及可独立运行的 MCP 服务组成。

```text
index.html / screenshot.html
        │
        ▼
TypeScript 页面入口与领域控制器
        │  api.ts（Tauri invoke / event 边界）
        ▼
Rust Tauri 命令与应用状态
        │
        ▼
文件系统、图像处理、窗口、热键、OCR、屏幕捕获
```

常规 GUI 以 Rust 创建窗口并加载页面。前端不直接调用操作系统 API；跨边界操作统一经 `src/api.ts` 调用 Tauri 命令或订阅事件。MCP 模式直接在 Rust 侧启动，不依赖 GUI 窗口和前端初始化。

## 运行入口

| 入口 | 职责 |
| --- | --- |
| `src-tauri/src/main.rs` | 进程入口。默认启动 GUI；`--mcp` 启动 stdio MCP 服务；`--mcp-http` 启动仅本机监听、需 Bearer Token 的 HTTP MCP 服务。 |
| `src-tauri/src/lib.rs` | 组装 Tauri 应用：管理状态、注册命令、插件、全局热键、托盘、单实例和窗口生命周期。 |
| `index.html` / `src/main.ts` | 主查看器窗口的页面骨架和前端入口。 |
| `desktop-pet.html` / `src/desktop-pet.ts` | 独立透明桌宠窗口；加载 Live2D 模型并在首帧绘制后报告就绪。右键显示截图、滚动截图、主界面和退出菜单。 |
| `src/ui/window-shell.ts` / `src/styles/window-shell.css` | 单个透明主窗口内的面板、角色前后景和接触阴影；共用坐标与缩放，截图隐藏绘制回执。 |
| `screenshot.html` / `src/screenshot.ts` | 截图窗口的页面骨架和组合入口。 |

## 前端目录

标注尺寸由 `src/image-editor/annotation-style.ts` 统一定义基础档位：线粗为 1/2/3/4/6/8/12 px（默认 2），字号为 12/16/20/24/32/48/64/72 px（默认 24），马赛克色块为 8/12/16/24/32/48 px（默认 16）。截图直接使用上述原图像素档位。图片编辑在图片显示、工具栏预留空间生效后，用实际画布 CSS 宽度与原图宽度之比初始化默认值和档位：缩小显示时除以预览比例并取整，默认预览约为 2 px 线粗、24 px 字号和 16 px 色块；以原尺寸显示时保持基础值。该初始化仅在打开新的编辑会话时执行，切换工具、旋转及调整窗口不重算已选大小。三类参数独立保留当前会话的选择，截图与图片编辑均直接存储原图物理像素；界面缩放只改变显示，不修改已有标注尺寸。文字输入框按画布显示比例缩放，测量和渲染共用字体与 1.2 倍行距。导出使用相同绘制路径；图片编辑选择缩小输出时，标注随图片等比例缩小。

单图属性栏仅在打开时查询 EXIF，读取在 Rust 后台任务中进行；JPEG 等容器由带缓冲的文件读取器交给解析库，避免预先把整张图片读入内存。预览条悬浮于画布底部中央，显示当前图片前后各两张缩略图，复用现有节点和有限缓存；当前项稍大，窄窗口下保持当前项可见。状态栏左端、文件名前的按钮可即时显示或隐藏预览，与设置页共用 `image_preview_strip_enabled` 的保存路径，不显示保存成功提示，保存失败仍会提示；隐藏预览不改变画布大小，按钮仅在单图查看时显示，文件名弱化显示并提供完整名称的悬停提示。

裁切拖动缓存坐标映射并通过 `frame-update.ts` 每个显示帧合并输入，松开时同步提交最后坐标，取消时丢弃待处理输入。`crop-viewport.ts` 在松开后用约 220 毫秒的缓出动画将保留区域居中并适配编辑区，图片、预览和裁切框同步更新，手柄尺寸保持固定；再次拖动会停在当前显示位置，取消拖动和系统减少动态效果偏好则直接到位。拖动期间固定显示变换；窗口大小与工具切换保留手动变换，撤销、重做和旋转后取消动画并重新适配，坐标与标注尺寸仍为原图像素。裁切模式显示框外保留原色的暗化参考图，切换到标注工具后只显示保留区域；重新进入裁切可向外恢复原图区域。`crop-preview.ts` 只采样编辑区内可见的原图范围，缓存原色和暗化预览（像素倍率最高 2），避免放大小裁切区时生成整张放大的预览位图。拖动只改变彩色预览的裁切范围与框线；图像内容、显示变换或窗口尺寸变化时才重建预览，不在移动事件里读取布局或处理原图滤镜。透明棋盘格只显示在图片和裁剪预览范围内，图片外部使用随主题调整的纯灰背景；独立的图片轮廓和裁剪框采用黑白双层边线。暗化通过预览 DOM 的 brightness 滤镜同时作用于图片和棋盘格，保持透明区域的框内外差异，源画布与导出不绘制棋盘格或边线。预览与原始导出像素相互独立。

图片编辑的底部工具栏由 `image-editor/toolbar.ts` 管理：历史与退出、标注工具、缩放、保存分为四组浮岛，当前工具的参数与绘图工具组放在同一列，在所有窗口宽度下均显示在绘图工具组上方并对齐该组中心，窄窗口时一起换行；历史组的「重置」按钮使用纯图标，悬停说明其恢复原图及可撤销的作用。绿色「保存选项」按钮只展开面板，面板包含格式、导出缩放，以及「另存为副本…」「覆盖原图…」两个带说明的操作；覆盖仍由编辑控制器请求确认。工具按钮保持固定宽度，参数区显示当前工具名称；刚进入编辑或取消选中时隐藏空闲的标注调整面板，选中标注后才显示调整提示和删除操作，绘图与裁剪工具仍显示各自的参数或操作；工具栏尺寸变化时为画布预留空间。编辑预览按可用空间适配，小图和小裁切区最多放大至 2 倍；标注模式缩放只改变显示；裁剪模式缩放会按固定取景框重新计算导出区域，原始图片与标注仍保留原图像素坐标。编辑状态与导出仍由查看器编辑控制器维护。

图片编辑的 Esc 与工具栏退出共用异步退出路径：存在未保存修改时，通过 `image-editor/confirm-dialog.ts` 的应用内确认框选择继续编辑或放弃并退出，不再依赖 WebView 的 `window.confirm`。`ui/navigation-guard.ts` 将拖入文件、截图打开、历史按钮、真正关窗及托盘/桌宠退出接到同一确认路径；窗口隐藏到托盘保留会话。未提交文字在询问前提交，保存期间退出先等待当前事务；`image-editor/save-controller.ts` 按会话和修订号提交保存，只清除实际保存版本的未保存状态。关闭后释放图像、标注画布和历史。主窗口的最终关闭单独使用仅作用于 main 的 `main-close` capability。

图片编辑与截图的常用标注、保存和关闭图标共用 `ui/icons.ts` 的线框路径，复制图标不使用固定白色填充。两处工具栏采用柔和绿底和下划线标识选中工具；截图保留紧凑尺寸与半透明背景。截图面板的次级底色与警告文字使用独立的深浅色主题变量，避免浅色模式继承过深卡片或低对比的黄色小字。

单图浏览的滚轮缩放、实际大小和适应窗口由 `single-image-controller.ts` 使用约 150 毫秒的缓出动画平滑切换。连续滚轮输入累积目标比例并从当前显示状态接续，缩放始终围绕鼠标下的图片位置；开始拖动时取消动画并采用当前显示比例与平移，避免跳到未到达的目标。拖动实时更新，切图、旋转、翻转和窗口布局变化取消过渡并直接适配；系统减少动态效果偏好下不播放缩放动画。

缩放栏按当前任务显示图标操作，并通过悬停提示和无障碍名称说明用途：标注和选择模式提供“完整显示”的四角图标及“原始大小（100%）”的 1:1 线框标记，分别查看完整图片与原图像素；裁剪模式只显示“重置取景”的重置图标，将图片居中铺满固定框，并隐藏 100% 操作及停用快捷键 1。快捷键 0 / 1 仍可用于完整显示（裁剪中为重置取景）与原始大小，但悬停提示只解释用途，不附加数字快捷键。裁剪中的缩放、平移和重置取景保持裁剪框的屏幕位置和大小。`crop-viewport.ts` 的 `fitImage` 对应用户操作，内部 `fit` 仅用于初始化、旋转和历史恢复等布局重建，避免重建布局时改写裁剪内容。

裁剪通过 `crop-transaction.ts` 保存进入前的裁剪、旋转和标注快照。取景先作为草稿，“应用裁剪”（Enter）统一记入一步历史，“取消裁剪”（Esc）恢复原快照；两者完成后返回选择模式。草稿有变化时切换工具会提示先应用或取消，保存与撤销/重做在裁剪期间也要求先结束草稿。旋转是主工具栏中独立的图标操作，每次向右旋转 90°，先提交正在输入的文字，再同步旋转图片、标注和已应用的裁剪区域，单独记入历史；裁剪期间置灰，要求先应用或取消裁剪。关闭编辑器会将待确认裁剪计入未保存修改；独立的选择按钮已移除；矩形、椭圆、箭头及提交的文字自动进入标注调整状态并选中新标注，画笔和马赛克保留连续绘制。再点绘制工具可继续画，再点当前工具可回到调整状态；调整状态可重新点选任意已提交的矩形、椭圆、箭头或文字，切换工具不会锁定旧标注；绘制模式的拖动只新增标注。画笔和马赛克不参与悬停、选中、移动或局部旋转，修正笔画使用撤销。文字输入后按 Enter、点击画布或失焦均提交并立即选中新文字；点击画布完成输入时不再开启另一个输入框，切换工具时仍以所选工具为准。`annotation-selection.ts` 管理悬停、点选、拖动与取消。命中容差和选中轮廓保持屏幕尺寸；覆盖层独立于导出画布，`annotation-frame.ts` 在标注局部坐标系生成固定尺寸的选框，选框与四角手柄随标注一起旋转，黑底白边的实心双向弧形光标按各角及当前标注角度以一度精度缓存；拖动期间捕获输入的画布使用当前角点光标，使弧形内侧始终朝向角点，缓存最多 360 个方向；被裁剪隐藏的角点不提供手柄。按住任意角点，按鼠标相对固定中心的方向变化旋转，累计跨越 ±180° 的变化，横向和纵向拖动均响应；经过中心 6px 范围时保留当前角度并重新锚定指针方向，避免翻转，标注尺寸、字号和笔触大小保持不变。中心标记仅用于提示，不可拖动；首次旋转时以标注包围框中心保存 rotationOrigin，后续旋转及重新选择不按变化后的包围框重算中心，避免不规则笔画漂移。移动和整图旋转会同步变换中心，历史快照深拷贝中心。`annotation-rotation.ts` 计算任意角度的标注副本，所有标注保留选框角度，矩形、椭圆和文字也用它绘制局部图形，箭头和笔画直接变换路径。旋转与移动共用逐帧合并、最终坐标提交、取消恢复和一步历史。绘制与命中使用同一局部坐标变换，整图 90° 旋转会同步已有局部角度。拖动按原图坐标移动选中的图形或文字（保留文字角度），限制在当前图片或已应用的裁剪范围内，每帧合并输入，松开时提交真实最终坐标并记为一步撤销；取消、丢失捕获或切换工具恢复原位置。点击空白取消选择，选中后上下文区显示“删除标注”，与 Delete 键共用可撤销的删除路径。历史工具组另提供“重置全部编辑”：取消正在进行的拖动和未确认裁剪，将正在输入的文字提交为可恢复标注，然后清除所有标注、裁剪和旋转并恢复原图预览；有效重置只增加一步历史，可一步撤销恢复重置前已应用的全部编辑。无修改时重置不制造历史记录。

### 主窗口数据流

顶部菜单由 `app-menu-controller.ts` 接管 `index.html` 的基础按钮，仅保留文件、截图、帮助三组，每组各三个操作且没有二级子菜单。文件包含打开图片、打开文件夹与设置；截图包含普通截图、滚动截图与截图设置；帮助包含快捷键说明、检查更新与关于。进入编辑、复制、分享与属性由图片右键提供，保存与撤销重做由编辑工具栏提供，排序与缩略图大小由网格原有控件提供。打开菜单时读取当前编辑状态，编辑期间将可能离开会话的操作置灰；快捷键说明使用浏览器模态层隔离底层编辑快捷键。“截图设置”直接定位截图分类，“检查更新”复用设置页的更新编排。菜单发起截图前等待页面完成一次绘制，避免将刚关闭的菜单捕获进截图。

快捷键说明采用居中的应用内双栏弹窗，按常用操作、截图、图片查看和图片编辑分组，组合键以独立键帽显示。主窗口中的 F1 从查看、编辑或设置页面打开同一弹窗，帮助菜单也显示 F1；该键只作用于当前窗口，不注册全局热键。监听在捕获阶段拦截默认帮助行为，重复按键不重复打开；弹窗隔离底层编辑快捷键，支持 Esc、关闭按钮及点击遮罩退出并恢复焦点。窄窗口改用单栏，低高度窗口仅滚动内容区，截图快捷键在打开时读取当前配置。

托盘由 `tray_menu.rs` 独立组装，仅保留显示主窗口、截图、滚动截图、设置及退出五项，没有快捷开关子菜单；放大镜和桌宠偏好统一在设置页管理。快捷键仅显示文字，仍沿用原有全局注册；配置、语言或截图热键改变后重建原生菜单以同步文案。设置通过 `tray-action` 发送类型化动作，主窗口显示后定位设置页；编辑未结束时提示先结束编辑。顶部截图经 `api.ts` 的 `startCapture` 调用同一后端入口。

`main.ts` 读取配置和启动参数后创建查看器会话。目录扫描、缩略图、图片属性、配置写入等需要原生能力的操作通过 `api.ts` 进入 Rust 命令；控制器把结果映射为网格、单图视图、图片编辑器或属性面板。图片编辑从工具栏、编辑菜单或右键菜单进入，读取可导出的 data URL，在前端 Canvas 中保持标注、裁剪和旋转状态，最后经 `save_edited_image` 写入所选格式。`image-editor-loader.ts` 在原页面保持可见时读取并解码编辑源，控制器绘制第一帧后再同步切换视图；切图或离开页面会取消待打开会话，过期结果不能重新显示编辑器。设置、菜单和窗口控制器只负责自己的 UI 边界，不保存查看器的核心状态。

### 截图数据流

应用首屏后在后台预建隐藏截图窗口，实际热键或命令触发时才抓屏，并向前端发送截图刷新事件。`screenshot.ts` 将事件交给生命周期和加载模块；加载模块先取得显示器元数据和截图编号，再经二进制 IPC 读取原始 RGBA 帧并绘制画布，报告就绪后显示窗口。关闭或刷新会话时以截图编号和加载序号阻止过期请求重新显示窗口，并释放本次像素。之后由编辑会话保存画布、选区和历史；输入、快捷键、工具栏与面板控制交互，渲染器负责画布重绘。普通截图可复制、保存或写入应用临时目录后在查看器中打开；复制、保存先得到后端成功结果，再短暂显示截图内确认并关闭，失败时保留选区。OCR 成功后也会将原选区写入临时目录并在查看器打开，识别文字显示在与属性、分享互斥的侧栏中；识别与主窗口加载之间用连续的进度提示衔接。滚动截图则由独立的会话、控制器、布局和 HUD 模块协调。

滚动截图统一使用 Enter 完成采集并进入结果预览、Esc 取消并退出；结果预览中 Esc 丢弃结果并关闭，Enter 复制。采集中也提供完成与取消按钮，鼠标穿透时显示键盘提示。原生宿主仅在采集期间临时注册 Enter/Esc，结束或出错均注销；取消会停止当前工作并拒绝迟到的进度、结果或失败事件，前端退出后也忽略旧事件。按键重复不会使一次完成操作继续触发结果复制。

截图坐标、图像像素与窗口缩放是高风险边界。涉及选区、拼接或导出的修改应优先复用 `src/screenshot/` 中已有的几何、布局和图像辅助模块，避免在页面入口重复换算。

马赛克先将未修改的源画布缩采样，再以最近邻放大成固定网格的色块纹理，连续圆头笔刷沿路径显示该纹理，笔刷直径与光圈一致。当前大小只保留一张纹理，切换大小时释放旧纹理；预览、提交与导出按相同顺序逐段绘制，避免停笔时边缘跳变，不从已涂抹画面取色。图片编辑与截图共用 `image-editor/annotation-layers.ts`：已提交标注单独缓存，当前马赛克笔画每帧仅补画新增路径并刷新其局部范围，鼠标输入合并到显示帧绘制。截图渲染器每次捕获只合成一次原始底图；使用马赛克时隐藏放大镜，避免逐帷取色；工具栏位置、根节点坐标只在选区、显示器或布局变化时更新。截图光圈复用输入控制器的物理鼠标坐标，按画布显示比例换算尺寸；更换捕获或重置会话时释放底图、纹理和标注缓存。

普通截图的源画布直接作为静态底图显示，`editor-renderer.ts` 只更新透明的标注画布。`selection-overlay.ts` 用四块 DOM 遮罩、边框和尺寸标签显示临时选区，选区及放大镜移动不再复制整张桌面；标注画布按选区显示裁剪，输入仍由覆盖层根节点接收。`magnifier-overlay.ts` 使用固定屏幕尺寸的小画布，15×15 采样通过一次最近邻放大显示，采样缓存按整数坐标与屏幕源失效。鼠标抬起提交真实最终坐标并同步刷新；关闭时清理各层及采样，滚动捕获开始前隐藏静态底图、选区层和放大镜，保留捕获区域的透明挖空。绘制次数对照与验证边界见 [选区拖动优化验证](screenshot-selection-smoothness-validation.md)。

选区显示样式由 `styles/screenshot/selection-overlay.css` 管理：默认边框是 1px 黑白交替细线，白段 8px、黑段 4px，无模糊暗影，在明暗背景和主题下使用同一套样式。设置 → 截图 → 选区框外观可切换到自定义模式，选择六位十六进制颜色及实线或虚线；自定义虚线采用 8px 彩色段与 4px 透明间隔。`selection_border_mode` / `selection_border_color` / `selection_border_style` 经配置持久化，每次截图刷新时由 `selection-overlay.ts` 应用到 DOM，旧配置默认沿用经典黑白虚线，已移除的点线配置自动回退为虚线，非法颜色在前端回退为白色。未选区域使用 65% 黑色遮罩，八个控制点以顶点或边中点为中心，保留黑白对比配色，尺寸标签使用白字深色底。上述元素只用于交互显示，不进入原图导出。普通截图工具栏定位由 `editor-ui-controller.ts` 调用 `overlay-layout.ts`，滚动截图定位由 `scroll-capture-layout.ts` 调用同一布局模块；当前布局的自动检查直接覆盖该模块，不依赖旧的独立几何演示脚本。

截图预热读取显示器的物理范围，按整个虚拟桌面的尺寸和位置创建隐藏窗口，并提前应用保存的界面倍率；不提前抓取桌面。实际截图仍以捕获元数据为准，只在内容尺寸或落点变化时调整窗口。内外框位置补偿集中在 `screenshot_window.rs`，避免每次复用先移到桌面原点、再移回补偿位置。负坐标副屏和上下错位的多屏布局也按物理包围盒准备。`sync_screenshot_window` 分步对齐原生位置和内容尺寸，等待 Windows 的异步调整完成后再设置子 WebView 范围，避免按旧父窗尺寸记录错误的自动缩放比例；父窗对齐后重写子视图范围，同时修复 WebView2 controller 残留的旧尺寸。前端 `viewport-ready.ts` 用 CSS 尺寸乘当前 WebView 的 DPR 核对完整桌面的物理宽高，连续两次稳定才继续渲染并报告就绪；DPR 只用于整窗校验，捕获和跨屏采样仍使用原始物理像素。未完成对齐的窗口不会显示，关闭或过期会话会取消等待，持续不匹配则释放该次截图并退出，避免把双屏压进单屏宽度。选区的四块 DOM 遮罩直接设置实际宽高，不再放大 1px 元素，避免混合 DPI 下的像素取整误差被放大成黑条。

Windows 进程入口在创建 WebView 和后台线程之前设置 `WEBVIEW2_DEFAULT_BACKGROUND_COLOR=00000000`，使网页组件从创建时就使用透明底色，规避创建后才设置透明产生的短暂白闪（[微软说明](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2controller2#put_defaultbackgroundcolor)）。截图 HTML 内联最小透明/隐藏样式，页面以 `visibility` 切换就绪状态，不做整体淡入；仍由截图编号校验与 `screenshot_ui_ready` 控制原生窗口显示。

截图窗口创建后关闭该 HWND 的 DWM 显隐过渡（`DWMWA_TRANSITIONS_FORCEDISABLED`），避免整张桌面背景随覆盖窗动画出现缩放体感。退出时先隐藏原生窗口，再发送 `screenshot-clear`；前端先撤销 `ready`，随后重置控件并释放像素，隐藏失败则不触发画面清理。

## 界面密度

前端使用固定 px 尺寸。`Config.ui_scale` 保存用户选择的界面倍率（100 / 110 / 125 / 150），旧配置缺字段时默认 100%，不再按显示器分辨率自动缩小。设置 → 常规 → 语言与外观 中修改后，`set_config` 保存偏好并通过 `ui_scale::apply_all` 立即同步主窗口和已创建的截图窗口。缩放经 `WebviewWindow::set_zoom` 写入，会重新排版并按设备像素绘制文字；Windows 显示缩放由 WebView 自己处理。

生效范围只包括主查看器和截图覆盖窗（`uses_ui_scale`），桌宠使用独立的缩放设置。窗口创建、截图窗口每次复用、换屏（`Moved` / `ScaleFactorChanged`）和页面加载完成时恢复保存的倍率；`ui_scale.rs` 缓存每个窗口最近一次成功应用的值，值未变时不触碰 WebView。截图界面在视口尺寸变化后重绘，输入和导出仍使用原始物理像素，不会因界面放大而改变截图尺寸。新增其它界面窗口时，在 `uses_ui_scale` 里登记，并在创建后调用一次 `ui_scale::apply`。

## 配置、类型与跨端契约

配置由 Rust 持久化，前端经 `api.ts` 读取和更新。跨端 DTO 的字段名、可选性与枚举值属于稳定契约：修改 Rust 命令、事件载荷或配置结构时，应同时检查 `src/api.ts`、调用控制器和相关单元测试。

前端接口遵循 Tauri 命令参数的实际命名约定。不要在 UI 控制器中散落 `invoke` 字符串或重复定义后端类型；先在 `api.ts` 增加封装，再向领域模块暴露语义化方法。

## 设置与临时缓存

设置页是主窗口内的整页视图：左侧按应用 / 截图 / 维护三组组织常规、查看、截图、快捷键和缓存五个分类，右侧设置行由 `settings-controller.ts` 的单一 `render()` 统一渲染，搜索词同时过滤分类与设置行。语言、主题、桌宠和软件更新位于常规；缩放灵敏度与相邻图片预览位于查看；放大镜、试验性自动滚动和局域网分享规则位于截图。每项改动立即写入配置，热键类改动需要显式「应用」。新增设置项时须同时补齐 `index.html` 的设置行、三条语言表的键与说明文案，以及 `AppConfig` 的 Rust/TypeScript 两端字段。

临时截图缓存只涉及应用自己的目录 `%TEMP%\CloverViewer`，用于保存普通截图和长截图「在查看器中打开」产生的 PNG。`get_cache_summary` 统计该目录的文件数与体积，`clear_temp_cache(older_than_hours)` 按最后修改时间删除（`0` 表示全部），并在应用启动时按配置的 `cache_cleanup_after_hours` 自动执行一次。维护逻辑只遍历该目录的普通文件：不跟随符号链接、不触碰系统 Temp 的其他内容，被占用而删除失败的文件只记录警告。缩略图另存于 Tauri 的应用缓存目录，最多保留 512 项或 128 MiB；缓存键包含原图路径、尺寸、文件大小和修改时间，因此原图更新后会自动生成新缩略图，旧项再按容量淘汰。

截图 OCR 成功后在查看器打开的原选区也写入上述临时目录。设置页的缓存清理不涉及缩略图目录或 MCP 的 `CloverViewer/mcp-captures`；MCP 的截图 ID、保留期与清理时机见 [MCP 使用指南](mcp-guide.md)。

局域网分享由 `lan_share.rs` 持有单个临时 HTTP 服务状态；前端只经 `api.ts` 调用 `startLanShare`、`startImageLanShare` 和 `stopLanShare`。服务向同一局域网暴露带随机令牌的预览与下载地址，内容只保存在内存；到期、达到一次下载限制或主动停止后即失效。`AppConfig` 保存默认有效期和下载限制，截图与查看器各自的分享控制器只负责其界面状态。

## 国际化

翻译键的类型由 `src/locales/zh-CN.ts` 导出，英语和日语翻译表通过 TypeScript 约束与其保持键集合一致。添加文案的顺序是：

1. 在中文词典添加键和值。
2. 在英文、日文词典补齐对应翻译。
3. 在界面中通过 `t()` 或 `data-i18n` 使用该键。

这使遗漏翻译在类型检查阶段即可发现，而不是在运行时回退为空文本。

## 审查整改后的会话与资源规则

`viewer/directory-loader.ts` 为打开和刷新共用请求序号，迟到或失败的请求不提交旧目录。F5/Ctrl+R 经 `viewer/refresh-shortcut.ts` 刷新目录并保留当前路径、排序和网格位置；编辑期间拦截 WebView 重载。导航历史刷新后按文件路径重映射，同目录另存副本会自动进入列表。AVIF 的缩略图、复制和分享经 `viewer/image-pixels.ts` 使用同源浏览器解码像素，原生格式复用 `image_io.rs` 的方向校正。

编辑预览的 `crop-viewport.ts` 支持滚轮、按钮与缩放快捷键，自动适配最多放大两倍，手动缩放范围为 5%–4000%，裁剪模式还受框覆盖与至少保留两像素的边界约束。`viewport-input.ts` 接收空格或中键平移；裁切和绘图拖动时保持变换稳定。裁剪模式的滚轮/加减缩放与图片平移固定框的屏幕位置和大小，反算原图裁剪范围并限制图像覆盖整个框；应用时统一进入历史，标注模式仍只调整预览。缩放按钮与倍率统一放入底部工具栏，随窗口宽度换行并计入画布预留高度。文字、矩形和椭圆标注保存局部旋转角度，共用绘制、命中与边界计算；笔画边界以循环求值，不展开长数组为函数参数。

缓存按条目与字节双重限制：单图解码 96 MiB，fallback data URL 按保守 UTF-16 估计 64 MiB，前端缩略图每个加载器 16 MiB，Rust 缩略图 32 MiB。撤销/重做总共最多 50 步，并按保守估值 32 MiB 淘汰旧步骤，至少保留最近一步。缩略图磁盘维护在启动时执行，并合并为每 16 次写入清理一次，容量阈值仍为 512 项/128 MiB，批次之间允许短暂超出阈值。

配置保存经 `ConfigStore::update_saved` 完整落盘后才提交；前端 `ui/config-writer.ts` 顺序保存独立补丁，失败只回滚该项并保留后续选择。普通设置成功时静默保存，滑杆在 input 时更新数值、change 时保存；失败恢复控件并提示。热键的「应用」、清理缓存与检查更新保留操作结果反馈，取色热键也等待保存成功后才提示。自启、桌宠、热键等系统副作用失败时恢复之前状态，持久化失败会返回 UI。`ui/theme-controller.ts` 共用系统主题 change 监听。

长截图结果由 Arc 持有，复制、保存和失败重试均不消费唯一结果，新会话或明确丢弃才释放。手动和自动会话共用安全高度估算，实际追加前再检查字节预算；达到上限保留已验证像素。普通与长截图导出的迟到回调不能关闭新截图会话。

局域网分享按 ID 停止并按请求代数提交；旧截图请求取消后不会展示旧链接，也不会撤销新的分享。`ui/share-status.ts` 每秒合并实际状态查询，下载一次、主动撤销或到期后显示已失效并移除或隐藏二维码、链接。停止请求等待后端确认，失败后保留重试及状态检查；查询失败或超过 5 秒未返回时显示暂时无法确认状态，恢复后继续倒计时。查看器与截图面板均按会话隔离迟到回调。编辑导出为静态 PNG/JPEG/WebP，不保留原始 EXIF/ICC；JPEG 固定质量 90 并把透明像素与白背景混合，PNG/WebP 保留透明度。

## 维护边界

窗口装饰由 `src-tauri/src/window_decoration.rs` 和 `window_shell_geometry.rs` 管理，偏好字段仍为 `window_decoration`（off/lean/peek）及 `window_decoration_scale`（60–140）。只有 main 一个透明原生窗口；前端将角色背景、实际 UI 面板、接触阴影和角色前景分层绘制。B 的身体被窗沿遮挡、手指位于前景；A 的坐姿和腿在前景，长飘带可被面板遮挡。物理留白与角色尺寸统一除以 devicePixelRatio 换算，独立于界面文字缩放；CSS 相对定位让移动和缩放无需跨窗口跟随。切换样式/大小保持可见面板尺寸和屏幕位置，持久化也只记录面板几何，防止重启后重复叠加留白；最大化和全屏去掉留白并隐藏角色。Windows 后台线程通过系统鼠标位置判断是否位于面板，透明留白及角色上启用整窗鼠标穿透，进入面板恢复交互。截图先发送角色隐藏状态，收到前端两帧绘制后的回执再抓屏，750ms 未响应才临时隐藏整个主窗口，结束后恢复。右键菜单按面板坐标定位，挂到 body 的下拉框限制在面板范围内。素材与遮罩记录见 [窗口装饰素材](window-decoration-assets.md)。

- 页面入口负责组合，不应重新吸收已抽出的状态、渲染或输入逻辑。
- 一个控制器应拥有一个清晰的状态和 DOM 边界；跨领域协调放在入口或专用编排模块。
- 修改截图交互时，优先补充或调整对应的领域模块，而不是直接向 `screenshot.ts` 堆叠事件处理。
- 修改用户可见文字时，同步维护所有语言表，并运行类型检查。
- 增加 Tauri 命令时，明确它属于 GUI 命令还是 MCP 服务能力；两者可复用底层领域模块，但不要让 MCP 依赖窗口状态。
- 文件行数仅是预警信号。详见 [业务源码文件行数规范](code-size-guidelines.md)。
