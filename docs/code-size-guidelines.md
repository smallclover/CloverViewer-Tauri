# 项目开发规范：业务源码文件行数

## 目的

控制单个业务源码文件的规模，使职责边界清晰、代码评审可读、测试定位直接，并降低修改同一文件时的冲突概率。
行数不是质量的唯一指标：内聚性、复杂度、依赖方向和可测试性优先于机械拆分。本规范将行数作为需要进一步检查的预警信号。**不要只为满足行数而拆分**：职责单一、结构和注释清楚、依赖合理的文件，即使略高于目标也可以保留。

## 适用范围与统计口径

本规范适用于产品运行时的业务源码：`src/**`、`src-tauri/src/**`，以及后续新增的同类目录。

- 以**有效代码行**为准：不计空行和仅包含注释的行；包含可执行语句、声明、标记和带行内注释的代码行。
- 不适用于自动生成代码、锁文件、配置文件、文档、图标和图片资源。
- 单元/集成测试、一次性诊断工具、发布脚本和示例代码不受硬性限制，但仍应保持单一测试或工具目的。
- 代码规模报告可同时列出物理行数，便于快速盘点；做评审判断时应使用有效代码行。

## 目标与处理规则

| 有效代码行 | 处理方式 |
| ---: | --- |
| 不超过 500 | 新业务文件的默认目标。 |
| 501–1,000 | 既有文件不因行数单独安排拆分；修改时检查职责是否混杂、测试是否困难。新增职责优先放入合适的模块。 |
| 超过 1,000 | 默认制定拆分计划，并优先在相关功能迭代中实施；暂不拆分时说明原因与职责边界。 |

以上门槛均按有效代码行判断。物理行数超过 500 只是盘点信息，不自动触发重构。即使低于 1,000 行，若一个文件已经混合多种职责、频繁发生修改冲突或难以测试，也应按实际问题提取模块；反过来，拆分不能只为满足数字而破坏内聚性。

## 允许例外

以下情况可以超过 1,000 行，但应在文件顶部注释或 PR 描述中说明原因：

- 自动生成代码或由外部协议、SDK 直接生成的绑定代码；
- 大型静态数据表、翻译资源或兼容性映射；
- 无法安全切分且拆分会显著降低可读性的高度相关实现；
- 测试夹具、探针程序或独立维护工具。

例外不应成为继续混入新职责的理由；当文件发生较大功能修改时，仍应重新评估拆分机会。

## 推荐拆分方式

- Rust：按领域职责创建子模块，使用 `mod.rs` 或同名目录组织；将平台 API 调用、数据模型、算法和 Tauri 命令边界分开。
- TypeScript：将状态、事件处理、渲染、领域计算和 Tauri API 调用分离；一个模块只导出紧密相关的能力。
- CSS：按页面或组件分组，统一保留设计 token/全局变量，避免按单条属性机械分文件。
- 先提取低耦合、已有测试覆盖的部分；每次拆分后保持行为不变，并补充模块级测试。

## 当前基线（2026-10-08）

按物理行数盘点，以下项目自有源码文件超过 500 行。它们目前都未达到 1,000 有效代码行，不需要仅因行数安排拆分：

| 文件 | 物理行 | 建议关注点 |
| --- | ---: | --- |
| `src/screenshot.ts` | 907 | 截图窗口组合入口；新增交互优先放入 `src/screenshot/` 中对应模块。 |
| `src/main.ts` | 798 | 主窗口组合入口；新增查看器逻辑优先放入 `src/viewer/` 或 `src/ui/`。 |
| `src-tauri/src/screenshot.rs` | 576 | 截图原生实现；屏幕像素与窗口创建已提取为独立模块。 |
| `src-tauri/src/scroll_capture/platform.rs` | 692 | 滚动截图平台交互；保持平台调用与算法边界。 |
| `src-tauri/src/scroll_capture/tauri.rs` | 645 | 滚动截图命令桥接；新增算法放入领域模块。 |
| `src/viewer/image-editor-controller.ts` | 674 | 图片编辑会话与导出；裁切、预览居中、工具栏、加载和共用标注图层已提取为独立模块。 |
| `src-tauri/src/mcp/mod.rs` | 553 | MCP 入口与组装；新增协议实现放入子模块。 |

`src/live2d-framework/` 是引入的框架源码，不按项目自有业务文件的行数目标拆分。多语言静态数据同样属于上文的例外。

页面骨架文件（`index.html`、`screenshot.html`）不计入本规范的统计口径。主窗口样式已由 `src/styles.css` 入口按职责拆分到 `src/styles/`；截图覆盖窗样式同样由 `src/styles/screenshot.css` 入口按基础、工具栏、编辑 UI、分享、滚动截图与提示拆分到 `src/styles/screenshot/`。

裁剪预览布局独立放在 `src/image-editor/crop-viewport.ts`；截图选区、放大镜和显示前尺寸校验分别放在 `src/screenshot/selection-overlay.ts`、`magnifier-overlay.ts` 与 `viewport-ready.ts`，避免把新的显示职责继续塞进入口文件。

以上文件均不要求一次性重写。只有出现明确的职责、测试或修改冲突问题时，才安排小步、可验证的提取。

## PR 自检清单

- 新业务文件是否尽量控制在 500 有效代码行以内？
- 修改 501–1,000 行的既有文件时，是否维持单一职责并避免混入新职责？
- 超过 1,000 行时，是否已拆分或记录了合理的例外与后续计划？
- 提取后的模块是否拥有清晰命名、单向依赖和相应测试？
