# OCR 结果阅读与选取方案 v1

日期：2026-10-24

状态：v1 设计记录，主要交互已实现；实际范围与验证结果见 [实现验证记录](ocr-interaction-validation.md)。

## 1. 目标与推荐方向

把当前“窄侧栏里的整篇文本框”升级为“原图定位 + 分块阅读 + 按需复制”。沿用当前 OCR 引擎及其识别文字，增加布局信息传递与结果交互。

首版应让用户完成三件事：

1. 快速看出哪些文字属于同一段。
2. 从图片或结果列表找到所需内容。
3. 复制一段、几段或段落中的一句话。

以本次聊天截图为例，期望将回复正文、验证说明、文件变更区域、最后一条消息分别组织。此为交互目标示例，不表示系统已能识别聊天角色或文件卡片语义；实际分组先依赖文字的几何位置。

## 2. 界面布局

### 原图区域

- 保留当前图片查看区，进入 OCR 结果后在工具区提供“选文字 / 浏览图片”切换，默认选文字。
- 默认不铺满识别框。指向某块时，显示淡绿色轮廓；选中后保留浅绿色覆盖和对应编号。
- 框线与编号保持固定屏幕尺寸；原图缩放、平移、旋转时，位置同步变换。
- “选文字”模式中，左键用于点选/框选文字，空格加拖动或中键用于平移，滚轮仍用于缩放。“浏览图片”恢复现有浏览手势。
- 退出 OCR 面板即移除选择覆盖层，释放相应事件和拖拽状态。

### 右侧结果区

建议默认宽度约 340 CSS px，允许拖动到 300–440px；宽度记在本次会话。当前侧栏为 280px。正文使用 14px、约 1.65 行高，跟随应用字体与界面缩放。

从上到下：

1. 标题“识别文字”与关闭按钮。
2. “分块 / 全文”两个视图。
3. 分块模式下显示“按段落 / 按行”的分组选择，默认按段落；以及全选/清空操作。
4. 可滚动的结果内容。
5. 固定在侧栏底部的选择数量、复制所选、复制全部；复制格式放在次级菜单。

分块列表以留白和细分隔线组织，不把每行包装成厚边框卡片。每块具有编号、勾选框、正文及编辑入口；选中时使用应用绿色，悬停状态更轻。操作不能只在悬停时才可用。

“全文”是按阅读顺序拼接的可选取文本预览；修改在分块内进行，两个视图使用同一份文本数据。已有仅含纯文本的结果可作为单个可编辑块显示。

### 小窗口

- 宽度足够时左右并排，侧栏扩展会重新适配图片。
- 应用内容宽度不足约 900px 时，结果区切到下方，避免把原图挤成窄条；实际断点需结合窗口装饰与界面缩放验证。
- 标题、视图切换与复制区保持可达，仅结果内容滚动。
- 中英日按钮文字可换行；125%–200% 界面缩放下不能遮挡操作。

## 3. 选取与复制规则

| 动作 | 行为 |
| --- | --- |
| 悬停原图文字块或结果段落 | 对应两处同步强调，不更改选中集合，不自动滚动侧栏 |
| 点击原图文字块 | 单选该块，侧栏滚动到该块；不改变原图缩放 |
| Ctrl + 点击原图文字块 | 增加或取消一个块 |
| 原图空白处拖框 | 预览并选择与框选区域相交的识别行；按所属段落汇总，支持只选段落中的部分行 |
| 点击结果勾选框 | 独立切换该块的选中状态，支持多选 |
| 点击结果正文 | 定位该块并强调原图，正文仍可按浏览器方式拖选字符 |
| 在结果正文拖选后 Ctrl+C | 优先复制拖选的字符，不被整块选择逻辑抢走 |
| 未拖选文字、未在编辑框内时 Ctrl+C | 复制已选块/行；没有选择时不触发复制 |
| 全选 / 清空 | 作用于块/行集合，不修改识别文字 |
| Esc | 先取消拖框或当前编辑，再清空已有选择，最后关闭结果面板 |

文本编辑框中的 Ctrl+A/C、撤销、方向键保留原生行为，不触发查看器快捷键。勾选框和编辑按钮支持键盘访问，状态带可读名称；高亮同时使用编号，不能只靠颜色区分。

复制始终按稳定的阅读顺序输出，不按用户点击的先后顺序。复制失败保留选择和文字，显示错误；成功仅在复制区短暂反馈。

### 两种复制格式

- **整理段落（默认）**：只合并已判定属于同段的软换行，块之间保留空行；保留用户手工编辑的换行。英文词间保留空格，中日文按文字规则连接。
- **保留原换行**：按 OCR 识别行输出。文件路径、列表、代码等内容优先用这一格式；它不承诺恢复原图的字体、缩进或表格列宽。

分组和复制格式是独立设置：用户可以按段落选择，同时保留识别行的换行。原始识别文字始终保留，不自动删掉按钮、时间戳或短文本。

## 4. 修改文字与分组异常

- 每块支持就地编辑；保存后同步全文与复制结果，取消则保留原内容。提供恢复该块原识别文字的动作。
- 编辑后的块仍关联原图原区域，表示内容来源，不声称新增文字拥有新的精确字符坐标。
- 一个块被手工编辑后，原识别行与新文字不再一一对应：该块改为整块选择，不允许框选原行后复制旧文字；“按行”视图将其显示为一个“已编辑”块。
- 在未编辑块中，按行视图与段落视图共享行 ID；切换视图不丢选择，部分行选中时段落勾选框为半选状态。
- 分组不合适时可切换“按行”，或在结果正文直接拖选所需字符。首版不加入手动合并/拆分/拖动排序编辑器。
- 没有坐标的历史纯文本结果仍可修改、选字和复制；原图定位控件不出现，不编造文字位置。
- 单个块很长时允许自然展开和连续选取，首版不默认折叠正文。大量结果可分批渲染，但不虚拟化正在进行的文本选区或编辑框。

## 5. 分组与阅读顺序

先保留识别行，再做保守段落分组。排序与分组应是独立、可测试的纯逻辑。

1. 规范化四边形坐标到 OCR 输入原图像素，保留行文本、方向与稳定 ID。
2. 根据稳定的水平重叠、左/右对齐和明显列间空隙区分区域。避免跨越大留白连接不同栏。
3. 在同一区域内，结合相对行高的垂直间距、缩进、对齐变化、方向判断是否合并；标点只作为辅助证据。
4. 方向变化、明显列边界、较大间距或不确定布局时，保留独立行。段落边界可以偏保守，不能为了减少条目吞并无关内容。
5. 首版重点覆盖单栏文字、常见界面截图和简单双栏。复杂表格、杂志多栏、竖排混排的自动阅读顺序列为已知限制，保留按行选择兜底。

不能按字符数等分文本框来宣称支持精确原图选字。首版原图选择单位是引擎实际返回的识别行/块；右侧正常文本仍能精确选到字符。

## 6. 数据与实现边界

### 现状

- `src/api.ts` 的 `ocrImage` 当前返回 `string`。
- 系统 OCR 可取得单词边界；Paddle 检测阶段已有四边形，但最终都拼成纯文本。
- Paddle 子进程用 JSON 返回 `Result<String, String>`，需要一并扩展。
- 截图 OCR 通过 `finishScreenshot` / `open-image` 传递 `ocr_text`，查看器按路径缓存字符串。
- 图片侧栏由 `src/viewer/image-ocr-controller.ts` 负责，样式目前在 `src/styles/viewer.css`。

### 建议的数据形状

以下为待实现的示意，实施时先定义 `src/api.ts` 的封装与类型，再同步 Rust：

```ts
interface OcrDocument {
  version: 1;
  imageWidth: number;
  imageHeight: number;
  text: string; // 原始纯文本投影，供兼容调用使用
  lines: Array<{
    id: string;
    text: string;
    quad: [Point, Point, Point, Point]; // 输入图片像素坐标
    confidence?: number; // 引擎确实提供时才携带，不用于自动隐藏文字
  }>;
}
```

前端派生段落、阅读顺序、选择集合和编辑内容。段落保留组成它的行 ID；不使用编辑后文本或数组下标充当稳定 ID。

GUI 增加结构化结果路径；保留旧纯文本调用和 MCP 输出语义，共用一次识别结果，不重复跑 OCR。`finishScreenshot` / `open-image` 增加可选结构化结果并兼容旧 `ocr_text`，主窗口桥接层和事件消费者一起更新。

系统 OCR 的缩小/增强预处理需要记录变换并还原坐标；Paddle 的分片偏移与去重也要保留。使用“本次用于识别并展示的图片”作为坐标基准，避免原始文件方向、截图偏移或缩放重复计算。

子进程结构化输出需要重新检查当前 4 MiB 输出读取上限，设置合理的结果字节数/行数限制，并测试截断错误；不能直接截断 JSON 或静默丢失尾部文字。

### 建议模块

| 模块 | 责任 |
| --- | --- |
| `src-tauri/src/ocr/result.rs`（新增） | 结构化结果、原文投影、坐标校验 |
| 现有 `ocr.rs`、`ocr/paddle.rs`、`ocr/worker.rs` | 两类引擎与子进程结果传递 |
| `src/ocr/layout.ts`（新增） | 识别行归一化、区域与段落分组、稳定顺序 |
| `src/ocr/selection.ts`（新增） | 行/块选择与复制内容派生 |
| `src/viewer/image-ocr-controller.ts` | 会话、视图切换与操作编排 |
| `src/viewer/ocr/`（新增） | 段落列表、就地编辑与原图覆盖层 |
| `src/styles/image-ocr.css`（新增） | OCR 专用布局、交互状态和响应式样式 |

图片坐标转换复用查看器实际渲染变换，不能重新建立一套近似缩放算法。异步结果按请求代数与图片身份提交；切图、重识别、图片修改后失效旧结果。缓存身份应包含图像版本信息，避免仅按路径命中被覆盖的旧图。

结果与编辑先保留在当前会话，不新增持久化 OCR 数据库。渲染文字使用文本节点，避免把识别出的 HTML 当作界面执行。新增产品文案三语同步。

## 7. 首版范围与后续

首版交付：结构化数据、保守段落分组、按行兜底、分块/全文视图、双向定位、点选/多选/框选、文字编辑、两种复制格式、窄窗口适配。

后续独立评估：原图逐字拖选、表格还原与 Excel 导出、聊天角色识别、语义分类、手动排版编辑、翻译和 AI 总结。这些能力不作为首版验收依赖。

按三步实施：

1. 完成两种引擎与截图到查看器的坐标契约，验证纯文本结果和识别精度不退化。
2. 实现分块/按行/全文视图及修改、选择、复制的统一状态。
3. 接入原图覆盖层、手势隔离、缩放旋转与窄窗口适配，完成真实桌面验收。

## 8. 验收条件

- 本次聊天截图中，用户能仅复制末尾消息，排除文件路径和按钮文字；分组不准时按行或正文拖选仍可完成。
- 不连续勾选多个块后，复制顺序稳定；清空、全选、半选、切换视图均正确。
- 悬停只强调，点击才定位；在原图定位时不突然放大或跳动。
- 原图缩放、平移、90° 旋转、不同 DPI 和界面缩放下，框与文字区域对齐。
- 原图/侧栏拖拽取消、失焦、切图及关闭面板后，不残留捕获或覆盖层。
- 右侧原生文字拖选、输入框复制和撤销优先，不能被全局查看器快捷键抢走。
- 修改一块后，两种复制格式和全文均使用新文字；部分行选择不会泄漏旧文本。
- 两种引擎、中文/英文/日文、短文本、长图、多栏和只有纯文本的结果均有样例覆盖。
- 旧请求迟到、同路径图片被覆盖、识别失败或空结果，不覆盖当前会话。
- 浅色/深色、窗口约 640px 宽、200% 界面缩放时操作可达；首版无需下载新模型。
- 实现完成后运行 `npm run check`、Rust 单元测试，并在真实 Windows 桌面验证选择与复制；仅单元测试通过不能代替交互验收。
