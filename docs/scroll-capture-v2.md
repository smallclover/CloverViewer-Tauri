# 滚动截图 V2：手动滚动优先

V2 的目标是输出一张可追溯到实际屏幕帧的长图，而不是尽可能“猜出”一张看起来完整的图片。
默认流程由用户控制滚动位置，程序只负责稳定采样、配准、拼接和反馈。自动注入滚动保留为试验性便利功能，不是质量基线。

## 不变量

1. 输出中的每一个像素都必须来自某一帧屏幕截图。
2. 只有配准器明确接受的帧才可以增加长图高度。
3. 固定顶部只来自首帧，固定底部只来自末帧。
4. 固定侧栏、滚动条和悬浮控件不能在单个线性长图中被诚实地表示；产品明确要求用户只选择正文 ROI，不尝试把它们“智能合成”。
5. 手动模式不会因连续的未匹配帧、动画、回滚或短暂静止而自动结束；这些帧只会被跳过，直到用户点“完成”/按 Esc，或达到已声明的资源上限。
6. 结束采样也必须通过同一套配准门槛：没有新增正文的末帧一律丢弃，避免重复尾帧。
7. 自动和手动模式共享同一个配准与拼接引擎；它们仅在“如何产生下一帧”上不同。

## 模块

`session_auto.rs` 与 `session_manual.rs` 是帧源和输入策略。`engine.rs` 保存最后一帧和画布状态，调用 `matching.rs` 生成唯一的配准结论，再调用 `stitching.rs` 追加真实的新条带。

`matching.rs` 对一对帧寻找纵向重叠，并只接受有足够纹理证据和像素支持的位移。`engine.rs` 只把**已接受帧**升级为可信锚点；未匹配、反向和相同帧均不会改写该锚点。这样用户在黄色“等待匹配”状态继续往下滚时，之后的绿色帧仍能从最后一个可信位置续接。

`session_manual.rs` 先用一次轻量探测判断画面是否变化；检测到变化后才等待目标稳定并送入引擎。它避免将浏览器半绘制帧作为拼接基准，也不会在用户未操作时反复执行昂贵的稳定等待。

## 验证

单元测试覆盖精确位移、固定首尾栏、相同帧拒绝、末帧不重复追加，以及未匹配帧后可恢复续接：

```powershell
cd src-tauri
cargo test --lib
```

真实 Windows 端到端验证继续使用 `tools/scroll-probe/`；应分别覆盖普通网页、带粘性首尾栏的网页、固定侧栏、重复列表、动态内容和滚动到底。手动模式的验收标准是：只在用户明确完成时结束、末帧不重复、未匹配帧不截断后续正文。
