# 截图选区拖动优化验证

日期：2026-10-08

普通截图已改为静态底图、透明标注、DOM 选区遮罩/边框和独立放大镜。拖动选区及移动放大镜不再清空或复制整幅桌面画布。放大镜的 15×15 采样改为一次最近邻放大，并缓存整数采样坐标及屏幕源；导出仍使用原始截图与标注。

## 绘制工作量对照

环境：无界面 Microsoft Edge，CSS 视口 1920×540，设备像素倍率 2；合成的截图为 3840×1080，带负坐标桌面原点。每次按住鼠标持续改变选区 120 个显示帧，每帧发送 10 个移动事件，分别开关放大镜。优化前后使用相同场景。

下表记录稳定拖动阶段及紧接着的鼠标抬起刷新；首次底图合成发生在统计开始前。

| 放大镜 | 指标 | 优化前 | 优化后 |
| --- | --- | ---: | ---: |
| 关闭 | 主画布整幅图片复制 | 240 | 0 |
| 关闭 | 主画布整幅清空 | 120 | 0 |
| 开启 | 主画布整幅图片复制 | 241 | 0 |
| 开启 | 主画布整幅清空 | 121 | 0 |
| 开启 | 全部 Canvas 的 `fillRect` 调用 | 28,282 | 121 |

以上数字证明移除了拖动路径中的整幅像素复制，并减少了放大镜绘制调用。它们不等于 GPU 合成耗时或实际 FPS。无界面浏览器的帧节奏不能代替 Windows 桌面 WebView2 的可见窗口测量，因此本轮不宣称已达到 60/120 Hz 的帧率目标。

## 自动验证范围

- `npm run check`：格式、lint、类型、单元测试及版本一致性检查。
- 补充验证了选区/放大镜移动不重画源图和标注、悬停框与选区遮罩的区别、缩放后标签保留物理尺寸、同像素采样缓存、新捕获与重置失效，以及缺失最后一次移动事件时的抬起坐标。
- 八组界面组合：缩放 1、1.25、1.5、2，各配合深色和浅色主题；模拟左侧负坐标显示器与上下错位的双屏。
- 界面检查覆盖原图和屏幕间空白、选区几何、独立放大镜的像素放大与取色、矩形/马赛克/文字、撤销重做，以及跨屏导出。导出未混入绿框、压暗遮罩或放大镜。
- 在原生滚动截图命令被调用时，检查静态底图、选区层和放大镜均已隐藏，根背景与捕获区域透明；完成态继续隐藏这些普通截图层。
- 每组组合连续关闭/重开截图 20 次，DOM 显示层数量保持固定，关闭时源画布和放大镜画布尺寸归零。
- 原有截图预热、多屏尺寸延迟对齐、窗口复用、取色及跨屏复制检查通过。
- 前一轮图片编辑裁剪自动居中功能不在本轮修改范围，仍需保留其已有检查。

本轮产品代码仅修改前端，未修改 Rust 或跨端契约。

## 仍待真实桌面验证

在用户实际双屏配置下对比优化前后的可见窗口帧间隔、首帧等待、p95/p99、浏览器绘制/合成跟踪与拖动观感，特别关注放大镜开启、高刷新率、混合 DPI 和双 4K 的情况。还需观察真实进程内存趋势；显示层数量与画布释放检查不能单独证明驱动或浏览器层没有内存增长。

如果仍不够丝滑，按照实际跟踪结果继续处理遮罩合成、采样读回或标注绘制，再比较额外合成层或 GPU 渲染方案。实施路径与验收目标见 [提案](screenshot-selection-smoothness-proposal.md)。
