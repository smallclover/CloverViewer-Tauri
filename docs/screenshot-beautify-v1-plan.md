# 截图美化首版实现计划

> 历史设计记录。2026-10-26 已精简为样式、背景、三档留白和简单水印；当前行为以 [图片美化](image-beautify.md) 为准。

日期：2026-10-25
状态：首版已实现，并按用户反馈整合到图片编辑器；第 9 节覆盖前文的弹窗与草稿交互设计。实施结果与验证边界见 [验证记录](image-beautify-validation.md)。
需求：截图之后可以自定义相框，以及添加不同形式的水印。

## 1. 首版目标与范围

提供统一的「美化」入口，让用户完成截图和标注后，为图片添加相框、文字或 Logo 水印，实时预览并输出成品。普通图片编辑复用同一套能力。

### 首版交付

| 能力 | 具体范围 |
| --- | --- |
| 相框 | 简约边框、纯色留白卡片、渐变背景卡片；均可关闭 |
| 相框参数 | 边框颜色与粗细、四边留白、图片圆角、阴影；渐变支持双色和方向 |
| 文字水印 | 多行文字、内置字体选项、字号、颜色、透明度、描边、旋转 |
| 图片水印 | 导入 PNG Logo，保持宽高比，调整尺寸、透明度、旋转 |
| 水印布局 | 单个定位或重复平铺；文字、图片都支持这两种布局 |
| 水印定位 | 九宫格锚点、边距、拖动定位；目标区域为截图内容或相框留白区 |
| 多水印组合 | 可添加、启停、删除、调整前后顺序；首版最多 8 层 |
| 模板 | 内置预设、保存个人预设、重命名、更新和删除个人预设 |
| 输出 | 普通截图复制、保存、打开查看器、局域网分享；图片编辑沿用现有保存流程 |
| 偏好 | 记住上次预设；「新截图自动应用指定预设」独立开关，默认关闭 |
| 基础体验 | 实时预览、应用/取消、撤销/重做、浅深主题、中文/英文/日文 |

首版「自定义相框」指通过参数组合并保存预设。上传装饰相框素材、九宫格切片相框、拍立得、浏览器/设备外框、批量处理、模板导入导出和工程文件留待后续。

滚动截图结果面板的直接美化入口另行实现。首版可先将长截图在查看器中打开，再进入图片编辑美化；该路径受图片编辑的尺寸与内存限制约束，不能据此宣称支持任意长度图片。

## 2. 用户流程与界面

### 2.1 普通截图

1. 完成选区和标注后，点击截图工具栏的「美化」。
2. 提交未完成的文字输入，结束当前指针操作，打开当前截图窗口内的美化工作面板。
3. 左侧显示完整成品，右侧按「预设 / 相框 / 水印」切换参数；窄屏改为上下布局，操作栏保持可见。
4. 参数调整即时更新预览，同时显示最终输出尺寸；提供适应预览和 100% 查看。
5. 点击「应用」提交此次美化并返回标注；点击「取消」或 Esc 丢弃此次草稿并返回。Esc 不继续传播为退出截图。
6. 面板也提供复制、保存、打开查看器和分享操作；这些操作先提交草稿，再调用现有截图动作，失败时保留当前会话并允许重试。

美化面板打开时，隔离底层框选、标注快捷键和鼠标输入。关闭时恢复原来的焦点。面板定位限制在操作所在显示器的可见区域，处理多屏负坐标和不同缩放。

返回标注后，原选区仍展示截图和标注，工具栏显示「美化已启用」及预设名，提供重新预览入口。最终成品始终在美化面板内展示，避免相框扩张后超出屏幕。

### 2.2 普通图片编辑

- 在现有图片编辑工具栏加入「美化」，复用面板、参数模型和渲染器。
- 裁剪草稿未结束时，按现有交互要求先应用或取消裁剪，再进入美化。
- 「应用」将美化参数作为一个编辑步骤提交；之后继续裁剪、旋转和标注时，重新以最新内容计算美化布局。
- 图片编辑面板通过应用后使用现有保存选项导出 PNG、JPEG 或 WebP，保留现有覆盖原图确认和退出保护。
- 已开启的美化参与未保存状态检测；重置原图同时重置美化，并可撤销。

### 2.3 预设与默认行为

- 内置「清爽分享」「渐变展示」「品牌配图」「资料标记」四套预设。品牌预设提示选择自己的 Logo。
- 预设可一键套用，修改后标记为「自定义」；保存个人预设只保存样式、文字模板和素材引用。
- 记住上次选择与自动应用分别控制。普通图片编辑默认不自动套用，避免重复美化已经导出的成品。
- 自动应用只在新普通截图会话初始化时执行一次。截图「打开查看器」输出的是扁平化成品，进入图片编辑时美化状态从关闭开始。
- 截图重新框选会清除该选区的标注和美化历史，再按自动应用偏好初始化；移动/缩放现有选区保留美化参数，重新计算布局。

## 3. 参数、坐标与输出规则

### 3.1 相框

- 相框向图片外扩展，不改变截图内容的宽高比。四边留白默认联动，可分别调整。
- 简约边框放在内容外侧；卡片支持纯色或双色线性渐变背景，图片圆角裁切和阴影。
- 留白不够容纳阴影时自动增加所需外扩空间，并在预览尺寸中体现，避免导出截断阴影。
- 无背景时保留透明区域；PNG/WebP 保留透明，JPEG 明确铺白底。格式切换后的预览应反映透明区域的实际输出效果。
- 首版不提供背景照片、纹理和任意渐变节点，以控制界面复杂度。

### 3.2 水印

- 单个水印以选定区域的九宫格锚点定位，再叠加偏移；拖动更新同一组坐标，不另存一套屏幕位置。
- 「相框留白区」明确选择上、下、左或右留白带；不存在足够空间时提示增加对应留白，不静默覆盖截图。
- 平铺按角度和横纵间距铺满目标区域，旋转后的边缘也要覆盖，并裁切到目标区域；内容水印受图片圆角约束。
- 多层按列表从下到上绘制，支持禁用和调整顺序。编辑手柄、选中框均不进入导出。
- 字体首版提供系统无衬线、衬线和等宽等有限选项，并配置中英日文回退；暂不开发系统字体管理器。
- 文字支持 `{date}`、`{time}` 两个变量。时间取自截图/图片编辑会话创建时的本地时间并冻结，避免预览与多次导出内容不同；未知变量按普通文字显示。

### 3.3 尺寸与缩放

- 单次会话以内容原始像素作为布局计算单位；UI 缩放、显示器 DPI 和预览缩放不得改变导出结果。
- 水印尺寸、留白等参数提供像素数值。保存跨图片预设时，将尺寸类参数按内容短边归一化，位置按对应目标区域归一化；套用后转换为当前图片像素并显示。
- 裁剪或旋转改变内容尺寸后，按归一化规则重新布局，并对圆角、边距、字体尺寸等应用合法范围限制。
- 图片编辑的导出缩放作用于完整成品，包括相框、水印和阴影；只做一次最终输出缩放。
- 输出顺序：裁剪/旋转与标注合成 → 计算相框及水印布局 → 背景与阴影 → 图片与边框 → 各层水印 → 最终缩放与编码。
- 预览和导出共用布局、文字测量和绘制函数。预览允许使用较小画布，但不能在小画布上重新决定换行、平铺间距或边界。

## 4. 状态、历史和持久化

### 4.1 会话状态

建议定义 `BeautifyDocument`，包含启用状态、相框参数和有序水印列表；每个水印具有稳定 ID、类型、布局、目标区域、样式和素材引用。

- 原图和标注仍由宿主编辑会话持有；美化文档只保存参数，不在历史中复制图片像素。
- 打开面板创建草稿副本；草稿内支持撤销/重做。滑块拖动、拖拽水印、连续文字输入按一次用户操作合并历史。
- 应用草稿后，只向宿主历史提交一个步骤；取消不改变宿主历史。应用后再次调整标注，撤销顺序必须符合实际操作顺序。
- 截图历史扩展为「标注 + 美化参数」，继续保持标注的选区局部坐标规则。
- 图片编辑 `EditSnapshot` 增加美化参数，更新克隆、恢复、重置和内存估算；改变参数增加修订号。
- 保存/分享开始时冻结内容、参数、变量和素材引用的同一修订快照。异步完成不能覆盖新截图、新图片或后续编辑。

### 4.2 预设与素材

通过 `src/api.ts` 先定义类型和命令封装，再实现 Rust 存储模块。建议采用独立的 `beautify.json` 和 `beautify-assets/`，位于现有配置目录之下，沿用应用的配置目录与便携回退规则。

| 数据 | 存储规则 |
| --- | --- |
| 美化偏好 | 自动应用开关、默认预设 ID、上次选择的预设 ID |
| 个人预设 | 稳定 ID、名称、版本号、归一化参数、素材 ID |
| Logo 素材 | 导入后复制到应用管理的素材目录，引用稳定 ID，不依赖原始文件继续存在 |
| 当前截图、当前图片像素 | 不进入预设文件 |
| 当前编辑草稿与历史 | 仅保留在会话内；首版不支持退出后恢复工程 |

计划提供读取美化库、保存偏好、增改删预设和导入/读取素材的领域命令，命名在第一阶段定稿。存储文件包含 schema 版本和库修订号，采用原子写入；并发更新基于修订号检测冲突，刷新后重试，避免主窗口与截图窗口互相覆盖。

无美化文件时使用默认值；损坏数据局部恢复并给出可理解的提示。Logo 导入校验实际格式、解码后像素数与大小；素材不存在或解码失败时要求用户替换或禁用该层，不能悄悄输出缺水印成品。

删除预设只解除引用。首版不在编辑期间立即删除素材文件，避免撤销历史和另一窗口仍引用它；素材清理机制后续单独实现。

| `src-tauri/src/lib.rs` | 注册新领域命令与必要状态 |

### 建议新增模块

在 `src/image-beautify/` 内按职责组织：`model.ts`（会话模型与校验）、`layout.ts`（纯布局计算）、`renderer.ts`（Canvas 合成）、`watermark-renderer.ts`（文字/图片与平铺）、`session.ts`（草稿事务）、`panel.ts`（面板组合）、相框/水印参数控件、`presets.ts`（内置预设与归一化）、`assets.ts`（素材加载与缓存）。

Rust 侧建立 `src-tauri/src/beautify/`，按模型校验、库持久化、素材导入和命令边界拆分。具体文件数随职责确定，不为了凑文件数拆分；新业务文件默认控制在 500 有效代码行以内。

沿用 `floating-ui.css` 的外壳、主题、焦点与按钮规则，美化工作区布局放在独立样式中。页面入口只负责连接模块。

截图现有编码返回纯 Base64，图片编辑编码使用 data URL；接入时明确各自边界，避免将一种载荷直接传到另一种调用路径。中间画布使用结束后及时释放。

## 6. 实施阶段与完成条件

| 阶段 | 工作内容 | 完成条件 |
| --- | --- | --- |
| P1 契约和布局 | 定稿首版参数、默认值、跨端模型、尺寸限制；实现布局与预设归一化 | 固定输入可得到确定的输出尺寸、内容区域和水印位置；旧配置可正常启动 |
| P2 共用合成 | 三种相框、文字和 Logo、水印定位/平铺、完整成品缩放 | 用真实 Canvas 验证相框、水印、透明和尺寸；预览与导出共用绘制路径 |
| P3 面板与事务 | 预览、参数面板、拖拽、草稿应用/取消、键盘隔离 | 用户能完成相框和水印组合，撤销/重做稳定，窄屏可访问所有操作 |
| P4 普通截图接入 | 工具栏、会话历史、统一导出、分享、自动应用 | 普通截图所有输出动作得到同一成品；OCR、重选、失败重试和连续截图通过回归 |
| P5 图片编辑与预设 | 编辑历史/保存修订接入；预设持久化、Logo 管理、偏好 | 裁剪/旋转后布局正确，保存和退出保护正确，重启后预设与 Logo 可用 |
| P6 验证与文档 | 多屏/主题/语言/格式/性能检查，文档更新 | 完成下方验收表和仓库检查，记录真实桌面验证结果 |

P1–P3 先打通纯渲染和面板；P4 形成普通截图闭环；P5 补齐首版完整交付。预设和素材的后端持久化可在契约确定后实施，但不跳过跨端契约先行顺序。

## 7. 验证与验收

| 场景 | 验收要求 |
| --- | --- |
| 关闭美化 | 输出尺寸和内容与现有截图/图片编辑结果一致 |
| 三种相框 | 参数调整正确，内容不被拉伸，边框与阴影完整 |
| 三类使用方式 | 文字署名、PNG Logo、斜向平铺均可单独使用，也可组合 |
| 定位 | 九宫格、拖动、旋转、切换目标区域后预览与导出位置一致 |
| 不同图片尺寸 | 小图、横图、竖图套用同一预设，参数比例与显示数值一致 |
| 多种导出比例 | 100%、50% 等现有比例下，完整成品尺寸和所有元素同步缩放 |
| 透明和格式 | PNG/WebP 透明正确，JPEG 铺底正确，半透明 Logo 无异常黑边 |
| 日期变量 | 会话内预览、复制、保存和分享得到相同时间文字 |
| 草稿和历史 | 应用为一步、取消恢复、连续调整合并、重置可撤销；标注与美化历史顺序正确 |
| 保存竞态 | 保存期间产生新修改或切换会话，旧结果不清除新修改、不污染新会话 |
| 多窗口配置 | 两窗口编辑预设或偏好时不静默覆盖；存储失败后可重试 |
| 素材持久化 | 删除原始 Logo 文件后预设仍可用；管理目录中素材缺失时提示替换 |
| 截图动作 | 复制、保存、打开和分享包含相同美化内容；OCR 不识别新增水印 |
| 快捷键与屏幕 | Esc 只关闭当前草稿；100%/150%/200% DPI、多屏负坐标下点击与拖动正确 |
| 界面 | 中英日文、浅深主题、窄窗口和长错误信息均可完整操作 |
| 内存与性能 | 4K 截图调整参数保持可交互；连续截图与反复开关面板后无持续资源增长 |

测试安排：

- 纯单元测试覆盖布局、旋转包围盒、归一化、参数边界、时间变量和历史事务。
- 在现有 `screenshot-actions`、`editor-export-image`、`editor-save` 等测试基础上扩展真实调用路径，覆盖输出一致性和异步失效。
- Rust 定向测试覆盖数据兼容、原子写入失败、修订冲突、素材校验与缺失处理。
- 真实 WebView2 桌面验证字体、透明、平铺缝隙、DPI 和剪贴板输出；仅靠模拟 Canvas 的单元测试不能确认视觉正确。
- 性能测量记录机器、图片尺寸、4K 调参延迟和峰值内存；目标为常规参数调整后约 100 ms 内呈现最新预览。预览按帧合并，过期渲染结果丢弃；大图提前校验边长、像素数及多画布内存预算，超过预算给出提示，不静默降低保存分辨率。
- 完成代码后运行 `npm run check`、`cargo test --manifest-path src-tauri/Cargo.toml --lib` 和 `npm run build`，并完成桌面交互验收。

## 8. 文档与后续

功能完成时更新 `docs/architecture.md`、相关交互说明和中英日三份 README，按实际实现描述能力。首版实现不调整发布版本，不向 `CHANGELOG.md` 添加未发布内容；发版另按 `docs/release.md` 执行。

后续优先级：滚动截图结果直接美化 → 拍立得/窗口外框 → 装饰相框素材适配 → 批量处理与模板分享。长图直接美化需要单独评估分块渲染或后端合成，避免简单复制普通截图的全尺寸多画布路径。

## 9. 编辑器整合修订（2026-10-25）

根据用户对首版界面和割裂流程的反馈，取消独立美化弹窗与单独的草稿历史，改为图片编辑工作区右侧的非模态参数栏。参数实时进入宿主历史；收起侧栏保留效果，保存、退出保护、缩放和平移全部复用原编辑器。预设改为缩略卡片，水印定位改为九宫格按钮，常用参数使用滑块。

`image-beautify/workspace.ts` 组装侧栏；`preview.ts` 将成品预览映射到原图坐标，并为原视口提供包含相框的显示范围；`watermark-input.ts` 管理水印拖动。原标注输入画布的坐标、裁剪几何保持原图像素，显示层另绘制带美化的成品。进入裁剪时临时恢复原图，完成后再合成。

普通截图点击美化时，以 `finish_screenshot` 的可选 `edit_context` 传入参数和原截图时间；主窗口直接进入图片编辑并展开参数栏。跨端契约先定义于 `src/api.ts`，Rust 校验后转发。传递的 PNG 包含已有截图标注，但不包含相框和水印，避免重复美化；已有标注在这一跳转中扁平化，之后新增标注仍保留编辑历史。
